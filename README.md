# Mini NPU Simulator

AI 가속기(NPU)의 핵심 연산인 **MAC(Multiply-Accumulate, 곱셈-누적)** 연산의 동작 원리를 파이썬 순수 문법(표준 라이브러리)으로 직접 구현하고, 크기별 연산 성능 및 부동소수점 오차 처리 정책을 검증하는 콘솔 애플리케이션입니다.

---

## 1. 프로젝트 소개

### 개발 목적
- **AI 연산의 본질 이해**: 현대 딥러닝/신경망 연산의 90% 이상을 차지하는 위치별 곱셈-누적(MAC) 연산을 외부 라이브러리(NumPy 등) 없이 2차원 리스트와 중첩 반복문으로 구현합니다.
- **패턴 인식 및 유사도 판별**: 입력된 숫자 패턴과 필터(십자가 `Cross`, `X`) 간의 MAC 연산 점수를 비교하여 더 유사한 형태를 자동으로 판별합니다.
- **수치 안정성 및 예외 처리**: 부동소수점 2진수 누적 오차를 극복하기 위한 허용오차(epsilon) 비교 정책과 다양한 입력 라벨을 정규화하는 데이터 처리 파이프라인을 구축합니다.
- **시간 복잡도 분석**: 데이터 크기($N \times N$) 증가에 따른 MAC 연산 시간과 연산 횟수($N^2$)의 상관관계를 실측하고 하드웨어 가속기(NPU)의 필요성을 분석합니다.

### 주요 기능
1. **모드 1 (사용자 직접 입력 모드)**: 3×3 필터 A, B와 패턴을 콘솔에서 직접 입력받아 점수 계산, 판정, 3×3 MAC 연산 시간 측정을 수행합니다.
2. **모드 2 (JSON 데이터 자동 분석 모드)**: `data.json`의 다중 크기(5×5, 13×13, 25×25) 필터 및 패턴을 일괄 로드하여 검증, 판정(PASS/FAIL), 크기별 벤치마크 및 결과 요약 리포트를 출력합니다.
3. **입력 검증 및 오류 회복**: 사용자 입력 시 열 개수 불일치나 문자 입력 시 프로그램을 종료하지 않고 안내 후 재입력을 유도하며, JSON 모드에서는 불량 데이터가 있어도 해당 케이스만 FAIL 처리하고 전체 분석을 완주합니다.

## 3. 핵심 구현 방식

### 1) 2차원 배열과 메모리 격리 (`src/matrix.py`)
- Python에서 `[[0]*n]*n` 형태로 2차원 배열을 생성하면 동일한 행 객체가 얕은 복사(shallow copy)되어 한 칸의 값을 수정했을 때 전체 행의 값이 바뀌는 심각한 버그가 발생합니다.
- 이를 방지하기 위해 반드시 독립적인 행 리스트를 생성하는 리스트 컴프리헨션을 적용하였습니다:
  ```python
  def make_matrix(n, fill=0):
      return [[fill for _ in range(n)] for _ in range(n)]
  ```

### 2) 순수 반복문 기반 MAC 연산 (`src/mac.py`)
- NumPy 등의 C 가속 라이브러리를 사용하지 않고, 2차원 리스트의 각 원소를 순회하며 곱셈과 덧셈을 직접 누적합니다:
  ```python
  def mac(pattern, filt):
      total = 0.0
      n = len(pattern)
      for i in range(n):
          for j in range(n):
              total += pattern[i][j] * filt[i][j]
      return total
  ```

### 3) 입력 검증 및 라벨 정규화 (`src/judge.py`, `src/mode_input.py`)
- 모드 1 콘솔 입력 시 `split()`을 통해 행당 원소 개수를 확인하고, `ValueError` 예외 처리를 통해 문자가 섞인 입력을 즉시 감지하여 친절한 재입력 안내 메시지를 제공합니다.
- JSON 데이터의 expected 값(`'+'`, `'x'`, `'X'`, `'cross'` 등)을 통일된 기준(`'Cross'`, `'X'`)으로 정규화하여 표기 불일치로 인한 오판을 원천 차단합니다. 알 수 없는 라벨은 `None`을 반환하여 스키마 오류로 격리합니다.

### 4) 부동소수점 오차 극복을 위한 Epsilon 비교 정책 (`src/judge.py`)
- 컴퓨터의 64비트 부동소수점(IEEE 754) 체계에서는 $0.1$과 같은 십진 소수를 2진수로 정확히 표현하지 못하여 $9 \times 0.1 = 0.8999999999999999$와 같이 미세한 오차가 발생합니다.
- 따라서 단순 등호(`==`) 비교 대신 허용오차 `EPSILON = 1e-9`를 기준으로 판정합니다:
  ```python
  if abs(score_a - score_b) < EPSILON:
      return "UNDECIDED"
  return "Cross" if score_a > score_b else "X"
  ```

### 2) 실패 원인 정밀 분석 (최소 10줄 이상 상세 서술)

1. **실패 케이스의 본질적 성격**: 이번 벤치마크에서 발생한 3건의 FAIL(`size_5_1`, `size_13_2`, `size_25_1`)은 프로그램의 코드 결함이나 구현 실수가 아니며, 데이터셋 설계자가 '수치적 동점 상황'을 의도적으로 부여한 검증용 케이스입니다.
2. **`size_5_1` 수치 분석**: X 패턴(1이 9칸)과 X 필터(모든 칸 0.1)의 MAC 연산은 $9 \times 0.1 = 0.9$가 기대되지만 부동소수점 누적으로 실제로는 `0.8999999999999999`가 계산됩니다. 반면 Cross 필터는 가운데 칸만 `0.9`이므로 겹치는 1칸과의 연산 결과 정확히 `0.9`가 됩니다.
3. **`size_13_2` 수치 분석**: 십자가 패턴(25칸)과 Cross 필터(모든 칸 0.3)의 연산은 $25 \times 0.3$으로 이론상 `7.5`이나 부동소수점 누적 합산값은 `7.499999999999997`이 됩니다. 반면 X 필터의 가운데 칸이 `7.5`로 지정되어 있어 X 점수 역시 `7.5`가 산출됩니다.
4. **`size_25_1` 수치 분석**: X 패턴(49칸)과 X 필터(모든 칸 0.1)의 연산 누적값은 `4.899999999999999`가 되며, Cross 필터 가운데 칸 `4.9`와 사실상 완벽한 동점을 이룹니다.
5. **단순 등호(`==`) 비교 시 발생하는 왜곡**: 만약 부동소수점 오차 정책 없이 `score_cross == score_x`로 동점을 판단하고 단순히 `>` 조건으로 판정했다면, `0.9 > 0.8999999999999999`로 인해 Cross 점수가 더 높은 것으로 판정되어 엉뚱하게 `Cross`라는 잘못된 판정 결과가 나오고 원인 파악이 어려운 '로직 오류'로 분류되었을 것입니다.
6. **Epsilon 정책의 효과**: 본 프로젝트에 도입된 `EPSILON = 1e-9` 정책을 통해 두 점수의 절대 차이($|a - b| < 10^{-9}$)가 기계적 오차 범위 내임을 감지하고 정상적으로 `UNDECIDED`(판정 불가)를 반환함으로써, 미세한 비트 오차에 의해 잘못된 판정이 내려지는 현상을 방지하고 '수치 비교 문제'로 정확히 분류할 수 있었습니다.
7. **라벨 정규화의 기여**: 데이터셋의 expected 라벨이 `'+'`나 소문자 `'x'` 등으로 일관되지 않은 상태로 제공되었으나, 전처리 단계의 `normalize_label()`이 이를 모두 표준 라벨(`Cross`, `X`)로 변환하여 문자열 불일치로 인한 거짓 실패(False Failure)를 완벽히 예방했습니다.
8. **데이터 유효성 검증 체계**: 행렬의 크기가 $N \times N$인지 검사하는 `is_square()` 및 키 파싱 방어 코드를 통해, 비정상적인 데이터가 유입되더라도 전체 프로세스가 크래시되지 않고 해당 케이스만 안전하게 격리되어 처리됨을 확인했습니다.
9. **향후 모델 및 데이터셋 개선 방향**: 실제 AI 모델 환경에서 이와 같은 동점 또는 판정 모호성을 해결하기 위해서는 필터의 가중치 초기화 시 대칭성을 깨뜨리는 난수(Random Weight)를 적용하거나, 필터 간 직교성(Orthogonality)을 강화하는 학습 손실 함수(Loss Function)를 추가해야 합니다.
10. **결론**: 본 시뮬레이터는 정규화, 입력 검증, 허용오차 기반 동점 처리라는 3단계 방어 설계를 통해 데이터 결함과 컴퓨터 수치 연산의 한계를 안정적으로 극복하도록 구현되었습니다.

### 3) 시간 복잡도 분석 ($O(N^2)$)

크기별 단일 MAC 연산(10회 반복 측정 평균)을 측정한 결과는 다음과 같습니다:

| 패턴 크기 ($N \times N$) | 곱셈·누적 연산 횟수 ($N^2$) | 실측 평균 시간 (ms) | 이론적 연산량 비율 ($N^2 / 9$) | 실측 시간 증가 비율 (3×3 대비) |
|:---:|:---:|:---:|:---:|:---:|
| **3×3** | 9회 | 약 0.0011 ms | 1.0배 | 1.0배 |
| **5×5** | 25회 | 약 0.0016 ms | 2.8배 | 약 1.5배 |
| **13×13** | 169회 | 약 0.0085 ms | 18.8배 | 약 7.7배 |
| **25×25** | 625회 | 약 0.0296 ms | 69.4배 | 약 26.9배 |

*(측정값은 실행 환경(CPU 클럭, 백그라운드 프로세스 등)에 따라 다소 차이가 있을 수 있습니다)*

#### 분석 내용
- **$O(N^2)$ 시간 복잡도의 근거**: 2차원 $N \times N$ 행렬의 MAC 연산은 외부 for문 $N$번, 내부 for문 $N$번 총 $N \times N = N^2$번의 곱셈 및 누적 덧셈 연산을 순차적으로 수행하므로 알고리즘의 시간 복잡도는 이론상 정확히 $O(N^2)$입니다.
- **실측 증가 비율이 $N^2$ 비율(69배)보다 작은 이유 (고정 오버헤드)**:
  - 3×3과 같은 작은 크기에서는 실제 곱셈 연산 시간보다 파이썬 인터프리터의 함수 호출(Function call), 지역 변수 프레임 생성, 루프 진입 등 고정 비용(Fixed Overhead)이 차지하는 비중이 매우 큽니다.
  - 데이터 크기가 25×25로 커질수록 고정 비용의 비율이 상대적으로 줄어들고 순수 연산 루프가 지배하게 되면서 점진적으로 $N^2$ 증가 추세에 근접하게 됩니다.
- **하드웨어 가속기(NPU)의 필요성**:
  - 범용 CPU는 직렬 처리 방식이므로 $N$이 커질수록 시간이 제곱에 비례하여 급격히 증가합니다.
  - 실제 영상 인식 딥러닝 모델에서는 수천만 개의 가중치 매트릭스에 대해 초당 수십~수백 회의 MAC 연산이 요구되므로, 수천 개의 연산기를 2차원 격자로 배치하여 한 클럭에 병렬 처리하는 전용 가속기(NPU의 Systolic Array 등)가 필수적입니다.

## 5. 보너스 과제 구현 (선택)

### 1) 1차원 배열 최적화 (`src/mac.py`, `src/matrix.py`)
2차원 리스트의 중첩 반복문(`for i in range(n): for j in range(n):`)은 매 반복마다 행 인덱싱 및 2차원 포인터 역참조 오버헤드를 발생시킵니다.
이를 길이 $N^2$인 1차원 리스트로 평탄화(Flatten)하여 단일 반복문(`for i in range(len):`)으로 연산하도록 최적화(`mac_1d`)를 구현하고 비교 측정한 결과입니다 (100회 반복 측정):

| 크기 ($N \times N$) | 2D 중첩 반복문 시간 (ms) | 1D 단일 반복문 시간 (ms) | 속도 향상 (Speedup) |
|:---:|:---:|:---:|:---:|
| 3×3 | 0.00090 ms | 0.00049 ms | **1.84배 향상** |
| 5×5 | 0.00162 ms | 0.00095 ms | **1.70배 향상** |

### 2) N×N 패턴 자동 생성기 (`src/matrix.py`, `tools/make_data.py`)
- `make_cross(n, val, center_val, bg)`: $n \times n$ 크기의 중앙 십자가 패턴 자동 생성
- `make_x(n, val, center_val, bg)`: $n \times n$ 크기의 두 대각선 X 패턴 자동 생성
