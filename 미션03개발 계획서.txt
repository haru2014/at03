# Mini NPU Simulator 개발 계획서

**프로젝트명:** AI가 계산하는 방식을 흉내 내는 작은 계산기 만들기  
**개발 언어:** Python 3.8 이상  
**개발 형태:** 콘솔 기반 프로그램  
**개발 도구:** VS Code, Python, 터미널  
**사용 라이브러리:** Python 표준 라이브러리만 사용  
**최종 제출물:** main.py, README.md (data.json은 제공 데이터 활용)

---

## Ⅰ. 프로젝트 개요

### 1. 개발 목적

AI의 핵심 연산 중 하나인 MAC(Multiply-Accumulate)의 원리를 이해하고 이를 파이썬으로 직접 구현한다.

숫자로 표현된 패턴과 필터를 비교하여 십자가(Cross) 또는 X 형태를 판별하는 프로그램을 개발한다.

또한 다양한 크기의 데이터를 분석하고, 계산 시간과 연산 횟수의 관계를 확인한다.

### 2. 핵심 학습 목표

1. 2차원 리스트를 이용하여 숫자 패턴을 저장하고 처리한다.
2. 이중 반복문을 이용하여 MAC 연산을 직접 구현한다.
3. 조건문으로 계산 결과를 비교하고 판정한다.
4. JSON 파일을 읽어 여러 데이터를 자동 처리한다.
5. 잘못된 입력에 대한 예외 처리를 구현한다.
6. 부동소수점 오차를 고려하여 판정 기준을 설정한다.
7. 연산 시간을 측정하고 시간 복잡도를 분석한다.
8. 테스트 결과와 실패 원인을 보고서로 작성한다.

## Ⅲ. 단계별 개발 계획

### 1단계. 개발 환경 구성 및 데이터 확인

**목표:** 프로그램을 실행할 환경을 준비하고 제공된 JSON 데이터 구조를 파악한다.

**수행 내용**

- Python 설치 및 버전 확인
- VS Code에서 프로젝트 폴더 생성
- main.py 생성
- data.json 파일 배치
- 터미널에서 파이썬 실행 확인
- JSON의 filters와 patterns 구조 확인
- 필터와 패턴의 크기별 키 확인

**확인 사항**

- filters 안에 size_5, size_13, size_25가 있는지 확인한다.
- 각 크기의 필터에 cross와 x 키가 있는지 확인한다.
- patterns 안에 size_N_idx 형식의 키가 있는지 확인한다.
- 각 패턴에 input과 expected가 있는지 확인한다.
- 실제 숫자 배열이 N×N 형태인지 확인한다.

**완료 기준:** 프로그램 실행 환경이 정상 동작하고, JSON 데이터의 실제 구조를 설명할 수 있다.

### 2단계. MAC 연산 함수 개발

**목표:** 두 개의 2차원 배열을 비교하여 점수를 계산하는 함수를 구현한다.

**수행 내용**

1. 2차원 리스트로 패턴을 저장한다.
2. 패턴과 필터를 함수에 전달한다.
3. 이중 for 반복문을 이용해 행과 열을 순회한다.
4. 같은 위치의 숫자끼리 곱한다.
5. 곱셈 결과를 하나의 변수에 누적한다.
6. 최종 점수를 반환한다.

**예시**

```python
def mac_score(pattern, filter_matrix):
    score = 0.0

    for i in range(len(pattern)):
        for j in range(len(pattern[i])):
            score += pattern[i][j] * filter_matrix[i][j]

    return score
```

실제 프로그램에서는 계산 전에 두 배열의 크기가 일치하는지 검증한다.

**기본 검증**

- 십자가 입력 + 십자가 필터 = 5점
- 십자가 입력 + X 필터 = 1점
- X 입력 + 십자가 필터 = 1점
- X 입력 + X 필터 = 5점

**완료 기준:** 위 네 가지 계산 결과가 정확히 출력된다.

### 3단계. 사용자 입력 모드 구현

**목표:** 사용자가 직접 3×3 필터와 패턴을 입력하여 결과를 확인할 수 있도록 개발한다.

**수행 내용**

1. 프로그램 시작 시 모드 선택 메뉴를 출력한다.
2. 사용자가 1을 선택하면 직접 입력 모드로 이동한다.
3. 필터 A를 세 줄에 걸쳐 입력받는다.
4. 필터 B를 동일한 방식으로 입력받는다.
5. 입력한 필터가 저장되었음을 출력한다.
6. 비교할 패턴을 세 줄에 걸쳐 입력받는다.
7. MAC 연산을 실행한다.
8. 필터별 점수와 판정 결과를 출력한다.
9. 3×3 연산 시간을 측정하여 출력한다.

**입력 검증**

- 한 줄에 숫자가 세 개가 아니면 다시 입력받는다.
- 문자나 잘못된 숫자가 들어오면 오류를 안내한다.
- 입력된 값은 float로 변환하여 저장한다.
- 유효하지 않은 숫자는 재입력하도록 한다.
- 세 줄을 모두 입력해야 다음 단계로 이동한다.

**판정 기준**

- A 점수가 더 높으면 A
- B 점수가 더 높으면 B
- 두 점수 차이가 1e-9보다 작으면 UNDECIDED

**완료 기준:** 올바른 입력으로 계산이 가능하고, 잘못된 입력에는 프로그램이 종료되지 않고 재입력을 요청한다.

### 4단계. JSON 데이터 자동 분석 모드 구현

**목표:** data.json 파일을 읽어 여러 패턴을 자동으로 분석한다.

**수행 내용**

1. 사용자가 모드 2를 선택한다.
2. data.json을 읽는다.
3. filters와 patterns 데이터를 확인한다.
4. 각 패턴의 키에서 크기 N을 추출한다.
5. 크기에 대응하는 필터를 선택한다.
6. 패턴과 필터의 크기를 검증한다.
7. 두 필터의 MAC 점수를 계산한다.
8. 계산 결과를 기준으로 패턴을 판정한다.
9. expected 값과 비교하여 PASS/FAIL을 표시한다.
10. 모든 패턴의 결과를 집계한다.

**라벨 정규화**

JSON의 라벨을 프로그램 내부에서 다음과 같이 통일한다.

| 입력된 값 | 표준 라벨 |
|---|---|
| + | Cross |
| cross | Cross |
| Cross | Cross |
| x | X |
| X | X |

필터의 키와 expected 값이 서로 다른 표기로 되어 있어도 동일한 기준으로 판정하도록 구현한다.

정규화할 수 없는 라벨은 임의로 해석하지 않고 오류로 처리한다.

**오류 처리**

- 필터가 없는 경우: FAIL
- 패턴 크기가 다른 경우: FAIL
- input 항목이 없는 경우: FAIL
- expected가 잘못된 경우: FAIL
- 숫자가 아닌 값이 있는 경우: FAIL
- 키 형식이 잘못된 경우: FAIL

오류가 발생한 패턴은 실패 목록에 기록하고 다음 패턴의 분석을 계속한다.

다만 JSON 파일 자체가 존재하지 않거나 파일 형식이 잘못된 경우에는 안내 메시지를 출력하고 분석 모드를 정상적으로 종료한다.

**완료 기준:** JSON의 모든 패턴에 대해 개별 판정 결과가 출력되고, 잘못된 데이터가 있어도 프로그램이 비정상 종료되지 않는다.

### 5단계. 부동소수점 오차 및 동점 처리

**목표:** 소수점 계산에서 발생할 수 있는 미세한 오차로 잘못 판정되지 않도록 한다.

**수행 내용**

두 필터의 점수를 직접 동일한지 비교하는 대신 허용오차를 적용한다.

```python
EPSILON = 1e-9

if abs(score_a - score_b) < EPSILON:
    result = "UNDECIDED"
elif score_a > score_b:
    result = "A"
else:
    result = "B"
```

JSON 모드에서는 A와 B 대신 Cross와 X를 반환하도록 구성한다.

**검증 항목**

- 두 점수가 정확히 같은 경우
- 두 점수의 차이가 1e-9보다 작은 경우
- 두 점수의 차이가 허용오차 이상인 경우

**완료 기준:** 미세한 점수 차이로 인해 판정 결과가 불안정해지는 문제를 방지한다.

### 6단계. 연산 성능 분석 기능 구현

**목표:** 패턴 크기에 따른 MAC 연산 시간을 비교한다.

**수행 내용**

1. 3×3, 5×5, 13×13, 25×25 데이터를 준비한다.
2. 각 크기에서 MAC 연산을 실행한다.
3. 시간 측정 함수로 실행 시간을 기록한다.
4. 각 크기에 대해 최소 10회 반복한다.
5. 측정값의 평균을 계산한다.
6. 연산 횟수 N²를 계산한다.
7. 크기별 결과를 표로 출력한다.

**측정 기준**

- 단일 MAC 함수 호출의 소요 시간을 측정한다.
- 파일 읽기와 출력에 걸리는 시간은 제외한다.
- 비교할 때에는 가능한 한 동일한 측정 조건을 유지한다.
- 10회 측정을 기본으로 하고, 값이 불안정하면 반복 횟수를 늘린다.

**성능 분석표 형식**

| 패턴 크기 | 곱셈 횟수 | 평균 시간(ms) |
|---|---:|---|
| 3×3 | 9 | 측정 후 기입 |
| 5×5 | 25 | 측정 후 기입 |
| 13×13 | 169 | 측정 후 기입 |
| 25×25 | 625 | 측정 후 기입 |

이 표는 필터 하나에 대한 MAC 연산을 기준으로 한다. 두 필터를 모두 계산하면 곱셈은 각각 N²회, 총 2N²회 수행된다.

**완료 기준:** 크기별 평균 연산 시간과 곱셈 횟수가 정확하게 출력된다.

### 7단계. 테스트 및 오류 수정

**목표:** 필수 기능을 모두 검증하고 예외 상황을 확인한다.

다음 테스트를 수행한다.

| 번호 | 테스트 내용 | 기대 결과 |

| T01 | 3×3 십자가 패턴 입력 | Cross 필터 점수가 높음 |
| T02 | 3×3 X 패턴 입력 | X 필터 점수가 높음 |
| T03 | 필터 점수가 완전히 같음 | UNDECIDED |
| T04 | 점수 차이가 epsilon 미만 | UNDECIDED |
| T05 | 입력 숫자 개수 오류 | 재입력 안내 |
| T06 | 문자 입력 | 재입력 안내 |

테스트 결과는 정상 동작 여부뿐 아니라 오류가 발생했을 때 프로그램이 계속 동작하는지도 함께 확인한다.

**완료 기준:** 모든 필수 기능 테스트가 요구된 결과를 출력한다. 의도적으로 잘못 만든 데이터는 정상적으로 FAIL 처리되어야 한다.

## Ⅳ. 핵심 함수 설계

main.py는 다음 함수들을 중심으로 작성한다.

| 함수 이름 | 담당 기능 |
|---|---|
| `main()` | 모드 선택 및 전체 흐름 관리 |
| `read_matrix()` | 3×3 숫자 입력 |
| `validate_matrix()` | 행·열·숫자 데이터 검증 |
| `mac_score()` | MAC 점수 계산 |
| `compare_scores()` | epsilon 기반 점수 비교 |
| `normalize_label()` | Cross/X 라벨 정규화 |
| `load_json_data()` | JSON 파일 읽기 |
| `analyze_patterns()` | JSON 패턴 일괄 판정 |
| `benchmark_mac()` | 반복 측정 및 평균 계산 |
| `print_summary()` | 테스트 통계와 실패 사유 출력 |

각 함수를 독립적으로 개발하고 검증한 후 main()에서 연결한다.
